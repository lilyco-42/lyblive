# Portable single-OBS deployment

Templates:

- `lyblive.service`: headless Web backend, `WantedBy=default.target`.
- `lyblive-obs.service`: one X11/XWayland OBS, `WantedBy=graphical-session.target`, `PartOf=`/`After=` the graphical session.
- `lyblive-obs`: clears Wayland/session-manager/activation variables and forces `QT_QPA_PLATFORM=xcb`, `XDG_SESSION_TYPE=x11`.
- `install.py`: read-only by default; `--plan` is an explicit alias; `--apply` writes backups, files, and enables units without restarting running services.

The installer derives `WorkingDirectory=` from its own repo path (`%h/<relative-path>` when under `$HOME`, otherwise an absolute path); the template itself only carries a `%h` marker. Unit files use systemd's `%h` specifier. `systemd --user` already passes the user manager's `DISPLAY`, `XAUTHORITY`, `XDG_RUNTIME_DIR`, and `DBUS_SESSION_BUS_ADDRESS` to services, so the templates do **not** hardcode a home/UID/display/cookie and do **not** use `PassEnvironment=` (a no-op for the user service manager). `%h` expands in unit files, but not in `systemd-run --property=Environment=...` values.

Usage after building the binary and Web assets:

~~~bash
python3 deploy/install.py --plan
python3 deploy/install.py --apply --bin target/release/lyblive
# Only after OBS has exited, to avoid its shutdown overwriting user.ini:
python3 deploy/install.py --apply --no-binary --configure-dock
~~~

Set `LYBLIVE_PORT` to change the Web port and dock URL together. `--configure-dock` preserves other docks and refuses to edit `user.ini` while OBS is running. `--fixture` is an offline-test mode that refuses the real home and implicitly skips systemctl calls; `--no-systemctl` is for users managing daemon-reload/enable themselves. `node scripts/ci-contract.mjs --deploy` verifies these templates in both CI jobs; archived snapshots checked with `--all-artifacts` skip source-tree deployment checks so older releases remain self-verifiable. `scripts/deploy-install-smoke.mjs` executes the installer against a temporary HOME fixture (read-only plan, apply, idempotency, port override, and input guards); both CI jobs and `scripts/single-obs-regress.sh` run it. The second apply is asserted per generated file (`label: unchanged`, no `: written`) so a `--plan` line containing `[unchanged]` cannot mask real rewrites. Both CI jobs pin Python 3.12 with `actions/setup-python@v5` before the smoke test; `ci-contract.mjs` guards both setup steps and their ordering, while `--all-artifacts` skips source-tree-only guards so archived releases remain self-verifiable. The smoke test also probes `python3`, `python`, and Windows `py -3` (asserting `sys.version_info >= (3, 7)`), so a runner image change cannot silently drop the interpreter. The CI contract parses exact step lines, adjacent version values, and requires a quoted `3.12` (`'3.12'` or `"3.12"`), so a YAML comment or unquoted `3.12` cannot fake the pin.

The dock writer uses Qt-equivalent INI parsing for [BasicWindow]: it tolerates leading whitespace and trailing comment text after "]", treats repeated [BasicWindow] sections as one logical section, and merges case-variant/indented ExtraBrowserDocks= keys into one canonical column-0 key. Linux QSettings keeps INI sections/keys case-sensitive, so the casefold key merge is a conservative anti-duplicate rule rather than a claim that Qt ignores case. Bad JSON and non-array JSON are refused. A missing [BasicWindow] causes a real section to be created (never a bare top-level key), a missing final newline is repaired, and read_raw() plus newline="" preserves CRLF through both plan and apply. A UTF-8 BOM is stripped before Qt-equivalent parsing and restored at byte 0 (BOM-preserving), and an unquoted ; inline comment terminates the dock value as QSettings readIniLine does. The smoke fixture asserts the BOM bytes, one canonical dock key, preserved [Panels] data, and strict second-apply idempotency. The offline smoke fixture covers duplicate sections, trailing-comment headers, case variants, another section whose dock must not be absorbed, missing sections, no-EOL endings, CRLF preservation, malformed JSON, UTF-8 BOM plus inline-comment preservation, and strict per-file idempotency. Immediately after `parse_args()`, the installer validates that `HOME` and `XDG_CONFIG_HOME` are absolute through argparse: `relative HOME` / `relative XDG_CONFIG_HOME` return rc=2 with `HOME must be an absolute path` / `XDG_CONFIG_HOME must be an absolute path` instead of a `RuntimeError` traceback or any writes; all five input guards assert a readable error and no traceback. Leading whitespace before a header is trimmed exactly as Qt readIniLine does, so an indented header such as "  [Other]" still terminates the previous section and its dock key is never absorbed into BasicWindow; the smoke test asserts the [Other] key survives while BasicWindow keeps only its own docks. The value scanner mirrors Qt readIniLine quoting: an unquoted ";" still ends the line, but a ";" inside a quoted run (for example a dock URL such as "http://127.0.0.1:9/api;jsessionid=abc") is preserved instead of being truncated into invalid JSON, and a backslash escapes the next character.

In --fixture mode, fixture write targets are confined to the temporary HOME: XDG_CONFIG_HOME, unit/bin destinations and --dock-ini are resolved through symlinks and must stay outside the real home. The offline smoke test rejects outside paths and symlink escapes, asserting the outside sentinel is unchanged and no directory is created. The guard also covers every output file, binary/backup symlinks and their resolved backup destinations; `backup_copy` / `atomic_copy` replace symlinks atomically from sibling temporary files, never writing through them. On Windows runners without file-symlink privilege, the offline smoke uses hard-link fallback to prove that atomic replacement never writes through a linked destination; both CI jobs run this forced fallback and `LYBLIVE_SMOKE_FORCE_NO_SYMLINK=1` reproduces it on any platform. The CI contract guards the exact step shape (one run per step, forced env value and normal-before-fallback order), so the hard-link fallback cannot silently drift into a disabled or duplicated step.

The canonical mode (`0644/0755`) is part of content idempotency: unit files are 0644, launcher/binary 0755, and missing, extra, or special bits are repaired with chmod on regular files only. `--plan` reports `mode repair` instead of a misleading unchanged state, and a `bad JSON` dock is validated `atomic`ally before any `--apply` writes; the offline smoke asserts that a stale unit sentinel and absent launcher remain untouched after the abort.

non-UTF-8 / Non-UTF-8 existing text is handled without a Python traceback: unreadable units are backed up byte-for-byte and replaced, while a malformed user.ini produces a readable argparse error before any unit/launcher write. A missing OBS dock is reported as `[create]` by `--plan` and created with canonical mode 0644 by `--apply`, but OBS is running blocks both editing and creating the dock to avoid racing a live Qt writer; OBS detection is capped by `OBS_DETECT_TIMEOUT = 5`, and a hung process lister becomes a readable `OBS detection timeout` refusal before any write. The offline smoke uses `LYBLIVE_SMOKE_OBS_STATE` to simulate clear/running/timeout deterministically on every CI OS, covering bounded OBS detection. A `dock symlink` is written through to its resolved target and preserved; `--no-binary` without an existing binary also returns a readable argparse error. The offline smoke exercises all four cases, including OBS-running and symlink-target sentinels.

Backups are collision-free even with a frozen-clock: the first backup uses `os.link` for `.dsh-portable-backup`, and every later backup keeps its unique sibling `mkstemp` name. No second-resolution timestamp or `os.replace(tmp, backup)` can overwrite an earlier version. The offline smoke freezes `time.strftime`, rewrites the same unit four times, and asserts all four original byte strings survive.


Before any `--plan` output or `--apply` write, `destination preflight` runs `check_write_target` on every output path and `check_readable_source` on the binary source. A non-regular destination (including `DO_NOT_TOUCH` sentinel directories and broken links), a `blocked parent` whose nearest existing ancestor is not a directory, an unreadable regular file, a non-writable parent directory (`parent directory is not writable`) or an unreadable source (`cannot read installer source binary`) becomes a readable argparse error with no partial writes. The offline smoke asserts both `--plan` and `--apply` reject directory, blocked-parent, 0000-file, 0555-parent, 0000-source and broken-link fixtures while preserving every sentinel. `unreachable-systemd preflight with bounded timeouts` probes `systemctl --user show-environment` before any `--apply` write; `--plan` prints `systemd --user: UNREACHABLE` and `--apply` exits 2 with no partial writes when the user manager is unavailable (for example outside a login session or when the tools are absent). `--no-systemctl` deliberately bypasses activation for manual `daemon-reload`/`enable`; the offline smoke hides the tools with `sitecustomize.py`, simulates `TimeoutExpired`, and asserts both the rejection and the `--no-systemctl` fallback. `SYSTEMD_TIMEOUT = 15` bounds every systemctl/systemd-analyze subprocess so a hung user manager cannot hang the installer. `HOME` and `XDG_CONFIG_HOME` values beginning with `~` are expanded explicitly from the real account home instead of `Path.expanduser()`; an offline fixture with `HOME=~` now yields rc=0, `HOME=/home/lilyco` and a readable service plan rather than `RuntimeError: Could not determine home directory.` CLI `--bin` and `--dock-ini` tilde paths use the same `user_path()` expansion: with fixture `HOME=~`, `~/missing-lyblive` yields rc=2 `--bin is not a file: /home/lilyco/missing-lyblive`, while `~/missing-user.ini --plan` prints `OBS dock -> /home/lilyco/missing-user.ini [create]` without writing to the real home; both have no traceback. A corrupt deploy bundle (missing `lyblive.service`, non-UTF-8 text, hardcoded `/home/lilyco`, or WorkingDirectory marker drift) is caught by `bundle_error()` while reading templates: it becomes a readable rc=2 `deployment template ... is invalid: ...; restore deploy/ from the release bundle` error before any plan output or write, never a Python traceback. The offline smoke copies deploy/ templates and install.py into four isolated fixtures and asserts each refusal with no write plan.
